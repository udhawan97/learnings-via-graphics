RAG that knows when to say “I don't know.”

The production engineering lesson isn't just connecting a search index to an LLM. It is building a system that retrieves authorized evidence, cites what it can support, tests what it can't, and safely abstains.

01 / Why care?

Your customer wants the right answer. Your boss wants proof.

Imagine a support assistant for a small e-commerce company. It knows the refund policy, but not the penalty in an unprovided enterprise contract. If it invents a penalty, you've built a liability. If it can cite the correct policy and abstain on the missing contract, you've built the beginnings of a trustworthy product.

Job-ready skill

Explain and implement retrieval, evidence thresholds, document-level permissions, tests, and the upgrade path to a managed search service.

Business value

Reduce unsupported answers and make the handoff to a human explicit. Measure quality before promising automation savings.

Reality check

RAG lowers some failure modes; it does not guarantee truth, remove prompt-injection risk, or enforce authorization by itself. [4]

Classification: FOUNDATION + 2026 PLATFORM CONTEXT. This is not a claim that RAG was newly invented in October 2026.

02 / Building blocks

Six pieces you should be able to draw on a whiteboard

01 · Chunk

A document passage small enough to retrieve and cite. Preserve stable ID, title, update date and access scope.

02 · Index

A data structure for retrieving passages by words, vectors, or both. Not the LLM's permanent memory.

03 · Embedding

A numerical representation used for similarity retrieval. Semantic proximity is not proof the answer is present.

04 · Reranker

A later scoring stage that sorts candidates according to relevance to the user's question. Often more latency and cost.

05 · Abstention

A designed output when authorized retrieved evidence doesn't support the requested conclusion.

06 · Evaluation set

Known questions with expected evidence IDs, supported/unsupported labels and checks for regressions.

Foundation rule

A convincing answer is not the same as a supported answer. Keep citation identifiers attached throughout ingestion → retrieval → answer composition. The model's prose must never be the only source of truth.

03 / Architecture diagram

The trustworthy answer pipeline

  1. Enforce access. Resolve identity and filter the corpus to documents the current user may see. Citation text cannot repair an authorization leak.
  2. Retrieve candidates. Keyword, vector or hybrid search can surface possible evidence; preserve source identifiers. [1]
  3. Check support. Did evidence actually answer the specific question, or merely mention related words? Try reranking and evaluate with held-out questions. [2]
  4. Generate narrowly—or abstain. Bound any model's output to authorized cited passages; evaluate the finished answer separately from search quality. [3]

04 / How current search actually works

Keyword search catches IDs. Vector search catches paraphrases.

Suppose the user asks: “What is the exact SKU-R7 return window?” Semantic vector search can understand “returns,” but an exact stock code is easy to miss unless literal text search contributes. Hybrid retrieval runs text and vector queries together and fuses the result rankings. Azure AI Search documents this pattern and optional semantic reranking. [1]

Keyword / BM25

Exact-match strength

Identifiers, SKUs, rare product names, numbers and specialized terminology.

Vectors / ANN

Paraphrase strength

“Send my money back” can match a passage about refunds without sharing the same words.

RRF / reranking

Combine candidate lists

RRF fuses ranked lists; a semantic reranker can then reevaluate candidates, with extra cost/latency.

In Azure's documented reciprocal-rank fusion, a result's contribution from one ranked list is approximately 1 / (rank + k), commonly with k = 60. Add contributions across ranked lists. [2]

Where people get it wrong

A high retrieval score is not a probability the answer is true. Never threshold arbitrary BM25, vector and RRF scores as if they share a universal confidence scale. Calibrate against labelled questions.

06 / The security boundary

Your documents can contain hostile instructions.

A PDF, retrieved page or support ticket might say “ignore previous instructions.” That sentence is untrusted content, even if retrieval ranks it highly. OWASP explicitly identifies indirect prompt injection through external content, and notes that RAG is not a complete mitigation. [4]

Permission test

Run a cross-tenant question and confirm the restricted chunk is filtered before generation.

Injection test

Put an instruction-like sentence in a retrieved chunk and check it cannot gain tool privileges.

Quality test

Measure unsupported claims and abstention behavior, not just plausible fluency.

NIST AI 600-1 (published July 26, 2024) frames generative-AI risks and life-cycle risk management. Use it alongside domain-specific threat modeling. [6]

07 / Build, test, then ship safely

The 18-minute offline guardrail lab

Here is a tiny **retrieval-only demonstrator**, deliberately without any LLM, embedding model, cloud credentials or network traffic. It shows three enforceable engineering habits: authorization filtering, an evidence threshold and an abstention path. It is not a production RAG system and its lexical matching is intentionally primitive.

Run these commands from this edition's folder

python3 offline_rag_lab.py
python3 -m unittest -v test_offline_rag_lab.py

Files: offline_rag_lab.py and test_offline_rag_lab.py. Requirements: Python 3.10+ for built-in generic type annotations, no packages or API keys. The code is an educational example with a miniature fictional policy corpus.

  1. Minutes 0–4: Read the three document IDs in DOCUMENTS. Notice there is no enterprise contract.
  2. Minutes 5–8: Run the script. The refund-window question quotes POL-001; the invented contract-penalty question says NOT ENOUGH EVIDENCE.
  3. Minutes 9–12: Run all five tests. One denies access to refund documents and checks no result is returned.
  4. Minutes 13–18: Change the query or threshold and observe a false negative. Explain why overlap count is not a calibrated confidence score.

Expected output excerpt

Q: What is the refund request window?
A: EVIDENCE [POL-001] A customer may request a refund within 30 days of purchase. A receipt is required.

Q: What is the enterprise contract cancellation penalty?
A: NOT ENOUGH EVIDENCE — ask a human or search an authorized source.

# unittest: 5 tests ... OK

What success really means

Passing tests establishes behavior only for this tiny sample corpus and five tested cases. It says nothing about enterprise retrieval accuracy, semantic search, jailbreak robustness, UI accessibility or customer production readiness. Those require a larger labelled dataset and real system evaluation. [3]

08 / Upgrade to a real product

From toy demo to an accountable assistant

  1. Ingest responsibly: preserve document IDs, version dates, tenancy/ACLs and deletion handling.
  2. Choose retrieval: establish a keyword baseline, then compare hybrid retrieval and reranking on the same labelled questions; store recall@k, MRR, latency and costs. [3]
  3. Implement a gated model: send only authorized evidence and source IDs to an LLM; reject or route unsupported outputs. Escape / separate untrusted instructions and restrict tools independently.
  4. Evaluate before release: run supported, unanswerable, adversarial and cross-tenant tests; review false answers and abstention rates with people who know the product's policy.
  5. Ship with observability: instrument end-to-end latency, retrieval IDs, model version, cost, user feedback and privacy-safe structured traces. Roll out narrowly, measure regressions, then broaden.

This article does not deploy an application, call cloud services or claim paid-service benchmarks. Research comes from Microsoft Learn, OWASP and NIST as listed below.

Dad's field rule

Knowing what you don't know is a technical advantage. At work and in life, a precise “I need to verify that” protects trust better than a confident guess. Make uncertainty observable and give it a safe next step.

09 / Knowledge check

Three questions to retain the lesson

1. Why is a perfect-looking citation not proof the answer is correct?

A citation can point to an irrelevant, stale or unauthorized passage. Verify that each claim is supported by the specific retrieved source, that the source was permitted, and that the answer addresses the actual question.

2. When does hybrid retrieval often help versus vectors alone?

When both literal identifiers (e.g. SKU-R7) and semantic paraphrases matter. Keyword/BM25 and vector searches cover different matching modes; RRF can fuse rankings. Evaluate on your own data rather than assume an automatic win.

3. What should happen if an authorized search finds no contract penalty?

Abstain explicitly, cite the lack of authorized supporting evidence as a product-state explanation, and ask for the correct contract or human escalation. Never invent a penalty or query another tenant's document.

60-second decision heuristic: Right user? Right sources? Enough support? Clear citation? Safe action? If any answer is “no” or unknown, stop or escalate.
